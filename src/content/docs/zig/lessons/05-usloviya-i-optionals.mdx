## Условие это bool

В C и Python `if (x)` работает с числами, указателями и строками. Ноль, `NULL` и пустая строка считаются ложью. В Zig условие имеет тип `bool`. Запись `if (5)` не собирается.

```
error: expected type 'bool', found 'comptime_int'
```

`if` это выражение. Оно возвращает значение, поэтому ты можешь присвоить его переменной.

```zig
const std = @import("std");

fn classify(n: i32) []const u8 {
    if (n > 0) {
        return "positive";
    } else if (n < 0) {
        return "negative";
    } else {
        return "zero";
    }
}

const label = if (10 > 5) "big" else "small";
```

`else` должен стоять на той же строке, что и закрывающая скобка. Причина в грамматике: Zig не требует скобок вокруг условия и не ставит точку с запятой после `if`. Перенос `else` на новую строку делает его отдельным оператором.

Короткие ветки ты пишешь в одну строку.

```zig
if (n > 0) return "positive" else if (n < 0) return "negative" else return "zero";
```

## Optional

`?T` означает либо значение типа `T`, либо `null`. Обычный `u8` не может быть `null`, поэтому проверка не появляется там, где ее не ждут.

```zig
var maybe: ?u8 = null;
maybe = 42;
```

Есть три способа достать значение.

```zig
if (maybe) |v| {
    std.debug.print("value: {d}\n", .{v});
} else {
    std.debug.print("null\n", .{});
}

const val = maybe orelse 0;
const unwrapped = maybe.?;
```

Захват `|v|` создает переменную только внутри ветки успеха. `orelse` подставляет значение по умолчанию. `.?` разворачивает optional без проверки и паникует на `null`.

Захват работает и в `while`.

```zig
var counter: ?u8 = 3;
while (counter) |c| {
    std.debug.print("countdown {d}\n", .{c});
    counter = if (c > 0) c - 1 else null;
}
```

Цикл печатает 3, 2, 1, 0 и завершается, когда `counter` становится `null`.

## Сколько стоит null

`@typeInfo` описывает optional одной структурой.

```zig
pub const Optional = struct {
    child: type,
};
```

Здесь только тип вложенного значения. `null` это отдельный тег, а не значение типа `T`.

Размер зависит от того, есть ли у `T` свободное значение.

```zig
@sizeOf(u8)   // 1
@sizeOf(?u8)  // 2
```

`u8` использует все 256 значений, поэтому для `null` нужен дополнительный байт. Компилятор хранит тег и payload отдельно.

```zig
@sizeOf(*u8)   // 8
@sizeOf(?*u8)  // 8
```

У указателя есть зарезервированное нулевое значение, которое не указывает на память. Компилятор использует его как `null`, и размер не растет. Та же оптимизация работает для `?enum`, если в enum есть неиспользуемое значение.

`null` существует в типе. Обычный `u8` не может внезапно оказаться `null`, и для проверки не нужен отдельный флаг.

## Где ломается

**Нет приведения к bool.** `if (5)` и `if (maybe)` не собираются.

```
error: expected type 'bool', found '?u8'
```

Для optional нужен либо `if (maybe != null)`, либо захват `if (maybe) |v|`. Захват безопаснее, потому что сразу дает значение.

**`else` на новой строке.** Код

```zig
if (cond) {
    foo();
}
else {
    bar();
}
```

не собирается с `expected statement, found 'else'`. Пиши `} else {`.

**`.?` паникует на null.** Это не проверка, а обещание, что значение есть. При нарушении в safe-режиме будет `panic: attempt to use null value` со стек-трейсом.

**`orelse` возвращает payload, а не optional.** Для `maybe: ?u8` выражение `maybe orelse "нет"` не собирается, потому что справа нужен `u8`.

**`?bool` это не три состояния.** Внешний optional отвечает на вопрос, есть ли значение. Внутренний `bool` отвечает на вопрос, истина это или ложь. Логически получается три состояния, но тип устроен как два уровня. `??u8` добавляет третий уровень и почти всегда означает ошибку проектирования.
