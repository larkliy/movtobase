## Три типа

В C массив при передаче в функцию превращается в указатель. Длину приходится передавать отдельно. В Zig массив, срез и многоэлементный указатель различаются на уровне типа.

- `[N]T` хранит ровно N элементов. Длина известна компилятору.
- `[]T` хранит указатель и длину. Срез не владеет памятью.
- `[*]T` хранит только адрес. Длина и границы неизвестны.

```zig
const std = @import("std");

pub fn main(init: std.process.Init) !void {
    var buffer: [1024]u8 = undefined;
    var out = std.Io.File.stdout().writerStreaming(init.io, &buffer);

    var arr = [_]u8{ 1, 2, 3, 4, 5 };
    const slice: []u8 = arr[1..4];
    const ptr: *u8 = &arr[0];
    const many: [*]u8 = @ptrCast(&arr);

    try out.interface.print("arr.len={d} slice.len={d}\n", .{ arr.len, slice.len });
    try out.interface.print("first={d} many[2]={d}\n", .{ ptr.*, many[2] });
    try out.flush();
}
```

`[_]u8{...}` создает массив, длина выводится из литерала. `arr[1..4]` создает срез на элементы 1, 2 и 3. `*u8` указывает на один элемент, `ptr.*` разыменовывает его. `[*]u8` указывает на последовательность неизвестной длины, `many[2]` выполняет адресную арифметику без проверки границ.

## Массив и срез

Массив передается по значению.

```zig
fn byValue(a: [4]u8) [4]u8 {
    var copy = a;
    copy[0] = 99;
    return copy;
}

var original = [_]u8{ 1, 2, 3, 4 };
const changed = byValue(original);
```

`original[0]` остается 1, `changed[0]` равен 99. Для больших массивов копирование дорого, поэтому передают срез или указатель.

Срез ссылается на чужие данные.

```zig
fn fill(s: []u8) void {
    for (s) |*b| b.* = 0;
}

var data: [8]u8 = undefined;
fill(&data);
```

`&data` имеет тип `*[8]u8` и приводится к `[]u8`. Функция получает указатель и длину, копирования нет.

## Sentinel

Zig хранит нулевой терминатор в типе.

```zig
const lit: *const [5:0]u8 = "hello";
const slice: [:0]const u8 = lit;
const cptr: [*:0]const u8 = slice.ptr;
```

`[5:0]u8` это массив из пяти байт с гарантированным нулем после него. `[:0]const u8` это срез, у которого после последнего элемента тоже есть ноль. `[*:0]const u8` это указатель с sentinel.

Обычный `[]const u8` не гарантирует ноль. Если C-функция ждет `char*`, нужен `[*:0]const u8` или `[:0]const u8`. Компилятор не даст передать обычный срез туда, где требуется sentinel.

## Выравнивание

У типа есть требования к адресу. `u32` обычно требует адрес, кратный 4. Если привести байтовый буфер к `*u32`, адрес может не подойти.

```zig
var bytes: [8]u8 align(4) = undefined;
const p: *u32 = @ptrCast(&bytes[0]);
```

`align(4)` гарантирует выравнивание массива. Если выравнивание неизвестно, применяют `@alignCast`.

```zig
const p: *u32 = @ptrCast(@alignCast(&bytes[0]));
```

`@alignCast` это обещание компилятору. Если адрес не кратен 4, safe-режим паникует, release дает UB.

## Байты и типы

Стандартная библиотека позволяет смотреть на одни байты разными типами.

```zig
var raw: [8]u8 align(@alignOf(u16)) = .{ 1, 0, 2, 0, 3, 0, 4, 0 };
const words = std.mem.bytesAsSlice(u16, &raw);
const back = std.mem.sliceAsBytes(words);
```

`bytesAsSlice` требует, чтобы длина делилась на размер элемента и выравнивание подходило. `sliceAsBytes` возвращает `[]u8` и работает всегда.

## Что под капотом

Типы указателей и массивов описаны в `lib/std/lang.zig`.

```zig
pub const Pointer = struct {
    size: Size,
    is_const: bool,
    is_volatile: bool,
    alignment: Alignment,
    address_space: AddressSpace,
    child: type,
    is_allowzero: bool,
    sentinel: ?usize,
};

pub const Array = struct {
    len: usize,
    child: type,
    sentinel: ?usize,
};
```

Срез описывается через `Pointer` с `size = .slice`. Длина хранится в значении среза, а не в типе. Многоэлементный указатель имеет `size = .many`, одиночный `size = .one`. Компилятор различает их и применяет разные проверки.

`std.mem.Alignment` это enum со степенями двойки.

```zig
pub const Alignment = enum(math.Log2Int(usize)) {
    @"1" = 0,
    @"2" = 1,
    @"4" = 2,
    // ...
};
```

Аллокаторы и `@alignCast` используют этот тип. Выравнивание здесь значение, а не число в комментарии.

## Где ломается

**Массив и срез разные типы.** `[4]u8` не присваивается в `[]u8` без среза или приведения. Обратное тоже не работает, потому что длина среза известна только в runtime.

**Границы среза проверяются.** `slice[10]` в safe-режиме паникует. У `[*]T` проверки нет, `many[10]` просто читает адрес. Многоэлементный указатель используют только там, где границы известны отдельно.

**Срез не владеет памятью.** `const s = arr[0..2];` живет, пока жив `arr`. Вернуть срез на локальный массив из функции нельзя, получится висячий указатель.

**`@ptrCast` не проверяет выравнивание.** После приведения к `*u32` адрес может быть не кратен 4. `@alignCast` проверяет обещание в safe-режиме.

**Sentinel это часть типа.** `[]const u8` и `[:0]const u8` разные типы. Приведение к sentinel-срезу требует, чтобы байт после конца действительно был нулем. Компилятор не всегда может это доказать.

**`@constCast` не делает память изменяемой.** Если объект лежит в read-only памяти, запись через `@constCast` это UB. Не используй его, чтобы обойти компилятор.

**Указатель на функцию не равен `*u8`.** Для кода ты берешь `*const fn (...)`, для данных `*T`. Смешивать их нельзя.

**`usize` не всегда 8 байт.** На 32-битных платформах это 4 байта. Для индексов и длин бери `usize`, если нужна переносимость.
