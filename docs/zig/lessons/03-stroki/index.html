    3. Строки¶

    Зачем это нужно и в чем прикол¶

    В C строка - это char*, который кончается нулевым байтом \0. Чтобы узнать длину, strlen бежит по памяти до этого нуля. Отсюда вся классика: забыл терминатор - читаешь чужую память, сравниваешь строки через == - сравниваешь указатели, "hello" в одном месте и "hello" в другом - это два разных адреса.

    В Zig никакой магии нет вообще. Строка - это просто срез байтов []const u8, а его длина лежит прямо рядом с указателем внутри структуры среза. Никакого скрытого нулевого байта, никакой неявной аллокации, никакого копирования при передаче. Две "одинаковые" строки - это два набора байтов одинаковой длины.

    Что это дает на практике: ты всегда знаешь длину за O(1), никто не сканирует память до нуля, и любая операция над строкой честно скажет, сколько байтов она трогает. А если тебе нужна C-совместимость, ты можешь попросить нулевой терминатор явно - об этом ниже.

    Базовый синтаксис¶

    Строковый литерал в Zig - это не char* и не объект, а указатель на массив с терминатором:

    const std = @import("std");

pub fn main(init: std.process.Init) !void {
    var buffer: [4096]u8 = undefined;
    var out = std.Io.File.stdout().writerStreaming(init.io, &buffer);

    const lit = "hello";
    try out.interface.print("literal type: {s}\n", .{@typeName(@TypeOf(lit))});
    // напечатает: literal type: *const [5:0]u8

    try out.flush();
}

    Разбираем *const [5:0]u8:

    • [5:0]u8 - массив из 5 элементов типа u8, а :0 - сентинел. Это значит, что сразу после пяти байтов лежит еще один байт со значением 0.
    • *const - указатель на этот массив.

    То есть "hello" в памяти - это 5 байт h e l l o и нулевой байт в конце, итого 6 байт, но длина строки - 5. Сентинел нужен именно для совместимости с C-функциями, которым нужен \0.

    Для работы литерал обычно приводят к обычному срезу:

    const name: []const u8 = "Heller";  // неявное приведение *const [6:0]u8 -> []const u8
try out.interface.print("name len: {d}\n", .{name.len});  // 6

    Приведение здесь бесплатное: компилятор просто "забывает" про сентинел и отдает тебе указатель плюс длину. А вот чтобы получить строку с гарантированным нулевым байтом на конце, есть тип [:0]u8 (срез с сентинелом) - он пригодится, когда будешь звать сишные функции.

    Дальше - операции:

    const a: []const u8 = "hello";
const b: []const u8 = "world";

// сравнение - ТОЛЬКО через std.mem.eql, == для срезов запрещен
const same = std.mem.eql(u8, a, a);

// поиск и проверки
try out.interface.print("{}\n", .{std.mem.startsWith(u8, "hello world", "hello")}); // true
try out.interface.print("{}\n", .{std.mem.endsWith(u8, "hello world", "world")});   // true
try out.interface.print("{?d}\n", .{std.mem.indexOf(u8, "hello world", "world")});  // 6

// срезы по байтам
const first_two: []const u8 = a[0..2];  // "he"

// итерация по байтам
for (a) |byte| {
    try out.interface.print("{c} ", .{byte});
}

    Обрати внимание на последний кусок: for по строке бежит по байтам, а не по символам. Про это - в разделе про подводные камни.

    Форматирование строк в этой версии Zig делается через std.mem.print (печать в готовый буфер) или через аллокатор alloc.print:

    var buf: [64]u8 = undefined;
const s = try std.mem.print(&buf, "name={s} age={d}", .{ "Heller", 42 });
try out.interface.print("built: {s}\n", .{s});

    Спецификаторы: {s} - строка, {d} - число в десятичной, {x} - в hex, {c} - символ по коду, {any} - что угодно (для отладки).

    Смотрим в сурсы: что там под капотом¶

    Начнем со сравнения. Вот std.mem.eql из lib/std/mem.zig:753:

    /// Returns true if and only if the slices have the same length and all elements
/// compare true using equality operator.
pub fn eql(comptime T: type, a: []const T, b: []const T) bool {
    // ...
    if (a.len != b.len) return false;
    if (a.len == 0) return true;
    if (@typeInfo(T) != .float and a.ptr == b.ptr) return true;

    for (a, b) |a_elem, b_elem| {
        if (a_elem != b_elem) return false;
    }
    return true;
}

    Никакой магии: сначала быстрая проверка длин, потом короткое замыкание "указатели совпали - значит это одна и та же строка", потом честный цикл по байтам. Для длинных строк выше по файлу есть еще векторная версия eqlBytes, которая сравнивает по 16-32 байта за раз через SIMD.

    Поиск подстроки. В этой версии indexOf переименовали в find, а indexOf оставили как совместимый алиас. Смотри lib/std/mem.zig:1436:

    /// Deprecated in favor of `find`.
pub const indexOf = find;

/// Search for needle in haystack and return the index of the first occurrence.
/// Uses Boyer-Moore-Horspool algorithm on large inputs; linear search on small inputs.
/// Returns null if needle is not found.
pub fn find(comptime T: type, haystack: []const T, needle: []const T) ?usize {
    return findPos(T, haystack, 0, needle);
}

    Строка - это данные, и алгоритм поиска тут честный: на больших строках Бойер-Мур-Хорспул, на маленьких - линейный перебор. Возвращает ?usize - опциональный индекс, null если не нашли.

    Форматирование. Раньше все писали std.fmt.bufPrint, теперь его вынесли в std.mem.print (lib/std/mem.zig:5209), а старый оставили с пометкой Deprecated. Вот сам print:

    pub const PrintError = error{
    NoSpaceLeft,
};

pub fn print(buffer: []u8, comptime format: []const u8, args: anytype) PrintError![]u8 {
    var w: std.Io.Writer = .fixed(buffer);
    w.print(format, args) catch |err| switch (err) {
        error.WriteFailed => return error.NoSpaceLeft,
    };
    return w.buffered();
}

    Смотри как красиво: это просто обертка над std.Io.Writer с фиксированным буфером. Не влезло - получаешь ошибку NoSpaceLeft, а не молчаливое переполнение как sprintf в C.

    А для динамического выделения - Allocator.print (lib/std/mem/Allocator.zig:486), который внутри сам резервирует память через std.Io.Writer.Allocating:

    pub fn print(a: Allocator, comptime format: []const u8, args: anytype) Error![]u8 {
    var aw = try std.Io.Writer.Allocating.initCapacity(a, format.len);
    defer aw.deinit();
    aw.writer.print(format, args) catch |err| switch (err) {
        error.WriteFailed => return error.OutOfMemory,
    };
    return aw.toOwnedSlice();
}

    То есть fmt.bufPrint и fmt.allocPrint в lib/std/fmt.zig:600 и :625 - это теперь тонкие Deprecated-обертки над mem.print и Allocator.print.

    Где можно споткнуться¶

    1. == для строк не работает. Попытка a == b на двух срезах дает ошибку компиляции:

    error: operator == not allowed for type '[]const u8'

    Это сделано намеренно: сравнение срезов неоднозначно (сравнивать указатели? содержимое?). Zig заставляет тебя ответить явно - std.mem.eql(u8, a, b) для содержимого.

    2. .len - это байты, а не символы. Строка "привет" содержит 6 символов, но каждый кириллический символ в UTF-8 занимает 2 байта, поэтому len вернет 12:

    const ru = "привет";
try out.interface.print("bytes: {d}\n", .{ru.len});              // 12
try out.interface.print("codepoints: {d}\n", .{try std.unicode.utf8CountCodepoints(ru)}); // 6

    И срез ru[0..2] отрежет ровно один символ "п", а ru[0..1] отрежет половину символа и даст битый байт. Zig честно работает с байтами; если нужна работа с символами - std.unicode.

    3. Литерал - это указатель, а не срез. @TypeOf("hello") это *const [5:0]u8. Пока ты не привел его к []const u8, у него нет поля .len в привычном смысле - у указателя на массив длина известна из типа. Обычно это не мешает, потому что приведение неявное, но в сигнатурах функций нужно указывать срез, а не указатель.

    4. Конкатенация ++ работает только на этапе компиляции. "foo" ++ "bar" сработает и даст литерал "foobar", но это потому что оба аргумента известны компилятору. Рантайм-строки так не сложить - для этого std.mem.concat (в аллокатор) или std.mem.print в буфер:

    var arena = std.heap.ArenaAllocator.init(std.heap.page_allocator);
defer arena.deinit();
const joined = try std.mem.concat(arena.allocator(), u8, &.{ a, b });

    5. Старые туториалы ведут по устаревшим именам. std.fmt.bufPrint и std.fmt.allocPrint помечены Deprecated и теперь живут как std.mem.print и Allocator.print. Если копируешь пример из старой статьи и видишь std.fmt.bufPrint - знай, что в свежем Zig это std.mem.print.

    6. Нет нулевого байта, если не попросил. Срез []const u8 ничего не знает про \0. Если отдаешь строку в C-функцию, нужен срез с сентинелом [:0]u8, иначе рискуешь утечкой чтения. Компилятор поможет: передать []const u8 туда, где ждут [*:0]const u8, не выйдет без явного приведения.
