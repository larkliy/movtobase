    17. Новый I/O в Zig 0.17¶

    Зачем это нужно и в чем прикол¶

    До 0.15 в Zig был std.io с getStdOut, bufferedWriter, reader и кучей отдельных типов. В 0.17 от него остались только воспоминания: ввод-вывод переехал в std.Io, а старые функции вроде std.io.getStdOut() удалены.

    Новая модель отличается тем, что I/O - это явный параметр. Рантайм создает реализацию std.Io (обычно std.Io.Threaded), кладет ее в std.process.Init и передает в main. Дальше вы передаете init.io в файлы, сокеты, таймеры и примитивы синхронизации. Никаких глобальных «стандартных потоков» и скрытых блокировок.

    Вторая важная идея - Reader/Writer - это интерфейсы. File.Reader и File.Writer содержат поле interface: Io.Reader/Io.Writer. Методы print, readAll, takeDelimiter живут на интерфейсе, а не на файле. Поэтому один и тот же код работает с файлом, сокетом, памятью и буфером.

    Базовый синтаксис¶

    Вывод¶

    const std = @import("std");

pub fn main(init: std.process.Init) !void {
    var buffer: [4096]u8 = undefined;
    var out = std.Io.File.stdout().writerStreaming(init.io, &buffer);

    try out.interface.print("Hello, {s}!\n", .{"world"});
    try out.flush();
}
    • std.Io.File.stdout() - файл стандартного вывода.
    • writerStreaming(init.io, &buffer) - writer с буфером. streaming означает, что позиция не сохраняется; для файлов с seek есть writer.
    • out.interface.print - форматированная запись.
    • out.flush() - сброс буфера. Без него данные могут остаться в буфере.

    Короткий вариант без ручного буфера:

    try std.Io.File.stdout().writeStreamingAll(init.io, "Hello!\n");

    Ввод¶

    var in_buffer: [4096]u8 = undefined;
var in = std.Io.File.stdin().readerStreaming(init.io, &in_buffer);

const line = try in.interface.takeDelimiterExclusive('\n');
try out.interface.print("line={s}\n", .{line});
    • readerStreaming создает reader с буфером.
    • takeDelimiterExclusive читает до разделителя, не включая его.
    • takeDelimiterInclusive включает разделитель.
    • takeByte читает один байт.
    • readSliceAll заполняет буфер целиком, readSliceShort - сколько получилось.
    • allocRemaining читает все до конца и выделяет память через аллокатор.

    Для бинарных данных есть takeInt, takeStruct, takeVarInt, takeEnum - все с явным endian.

    Файлы и каталоги¶

    const cwd = std.Io.Dir.cwd();

try cwd.writeFile(init.io, .{
    .sub_path = "demo.txt",
    .data = "hello from Zig\n",
});

const data = try cwd.readFileAlloc(init.io, init.gpa, "demo.txt", .limited(1 << 20));
defer init.gpa.free(data);

var file = try cwd.openFile(init.io, "demo.txt", .{});
defer file.close(init.io);

var file_buf: [1024]u8 = undefined;
var reader = file.readerStreaming(init.io, &file_buf);

    std.Io.Dir заменил старый std.fs.Dir в новых программах. Dir.cwd() возвращает текущий каталог, openFile, createFile, readFileAlloc, writeFile, iterate принимают io.

    Итерация по каталогу:

    var dir = try cwd.openDir(init.io, ".", .{ .iterate = true });
defer dir.close(init.io);

var it = dir.iterate();
while (try it.next(init.io)) |entry| {
    try out.interface.print("{s} {any}\n", .{ entry.name, entry.kind });
}

    Таймеры и сон¶

    const start = std.Io.Clock.Timestamp.now(init.io, .awake);
try std.Io.sleep(init.io, std.Io.Duration.fromMilliseconds(50), .awake);
const elapsed = start.untilNow(init.io);
try out.interface.print("elapsed={d}ns\n", .{elapsed.raw.nanoseconds});

    std.Io.Clock - enum часов. .awake - монотонные часы, которые не идут во время сна системы (по возможности). .real - системное время. Для бенчмарков используйте .awake или .monotonic.

    Почему interface?¶

    File.Writer - это структура с буфером и файлом. Она реализует Io.Writer, но не наследует его. Поле interface - это встроенный vtable + буфер. Поэтому:

    try out.interface.print(...); // правильно
// try out.print(...);        // ошибка: у File.Writer нет print

    То же с reader: in.interface.takeDelimiterExclusive(...).

    Смотрим в сурсы: что там под капотом¶

    std.Io в lib/std/Io.zig - это большой интерфейс с vtable:

    pub const Io = struct {
    userdata: ?*anyopaque,
    vtable: *const VTable,
};

    VTable содержит операции для файлов, каталогов, сокетов, таймеров, синхронизации. Конкретная реализация - std.Io.Threaded в lib/std/Io/Threaded.zig, std.Io.Uring для io_uring, std.Io.Kqueue для BSD/macOS. Выбор зависит от target и настроек рантайма.

    File в lib/std/Io/File.zig - это handle плюс флаги. stdout(), stderr(), stdin() возвращают File с нативным handle (на Windows - из PEB, на POSIX - файловые дескрипторы 0/1/2).

    File.Writer в lib/std/Io/File/Writer.zig содержит file, io, interface: Io.Writer, err. writerStreaming вызывает File.Writer.init с режимом streaming. Io.Writer в lib/std/Io/Writer.zig - это буфер, позиция и vtable с write, flush, rebase.

    Io.Reader в lib/std/Io/Reader.zig устроен похоже: буфер, seek, end, vtable. takeDelimiterExclusive ищет разделитель в буфере, при необходимости дочитывает файл и возвращает срез во внутренний буфер. Поэтому возвращенный срез живет до следующего чтения.

    std.Io.Dir в lib/std/Io/Dir.zig - новый файловый API. Он принимает io в каждом методе, потому что операции могут быть асинхронными и отменяемыми.

    Где можно споткнуться¶

    1. Забыли flush. Как и в старом API, буферизованный writer не отправляет данные сразу. Без flush вывод может не появиться.

    2. std.io.getStdOut() больше нет. В 0.17 используйте std.Io.File.stdout(). Старые туториалы не соберутся.

    3. .interface обязателен. File.Writer не имеет методов print/writeAll; они на Io.Writer. Ошибка no field or member function named 'print' - верный признак.

    4. Буфер должен жить, пока жив writer. writerStreaming(init.io, &stack_buffer) хранит указатель на буфер. Если буфер локальный и writer вернули из функции, получите висячий указатель.

    5. Reader возвращает срезы во внутренний буфер. takeDelimiterExclusive возвращает []u8, который действителен до следующего чтения. Если нужно сохранить - скопируйте (dupe) или используйте allocRemaining.

    6. Streaming и positional - разные режимы. readerStreaming/writerStreaming не используют seek и подходят для сокетов и pipe. reader/writer используют позицию файла и подходят для обычных файлов.

    7. Ошибка error.Canceled. Новый I/O умеет отменять операции. Если вы используете Io.concurrent/Future, будьте готовы к error.Canceled и не глотайте его.

    8. std.Io.Dir.cwd() не открывает каталог для итерации. Для iterate() нужен openDir(..., .{ .iterate = true }), иначе получите ошибку доступа.

    9. readFileAlloc требует лимит. Передавайте Io.Limit, иначе большой файл может исчерпать память.

    10. Не смешивайте старый и новый API. std.fs.File и std.Io.File - разные типы. В новом коде держитесь std.Io.
