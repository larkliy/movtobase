    6. Циклы while и for¶

    Зачем это нужно и в чем прикол¶

    В Zig ровно два цикла - while и for. Никакого do..while, никакого сишного for (i = 0; i < n; i++) с тремя выражениями через точку с запятой. Два инструмента, каждый с четкой ролью.

    while - это цикл с условием. Его фишка в отдельном выражении продолжения:

    var i: u8 = 0;
while (i < 3) : (i += 1) {
    // тело
}

    Условие i < 3 и шаг i += 1 разделены. Шаг выполняется после каждой итерации, включая итерацию, из которой ты сделал continue. Такой синтаксис убирает целый класс ошибок, когда в сишном for забываешь про i++ в теле с continue.

    for - это цикл по коллекции: массиву, срезу, диапазону. Индекс не надо считать руками, он всегда под рукой:

    for (arr, 0..) |item, idx| {
    // item - элемент, idx - его индекс
}

    А еще for умеет идти по нескольким последовательностям сразу, и циклы можно помечать метками, чтобы break/continue управляли нужным уровнем вложенности.

    Базовый синтаксис¶

    Простой while:

    const std = @import("std");

pub fn main(init: std.process.Init) !void {
    var buffer: [4096]u8 = undefined;
    var out = std.Io.File.stdout().writerStreaming(init.io, &buffer);

    var i: u8 = 0;
    while (i < 3) : (i += 1) {
        try out.interface.print("i={d}\n", .{i});
    }
    // печатает 0, 1, 2

    try out.flush();
}

    while умеет захватывать optional и error union - это мы уже видели в прошлых уроках:

    var counter: ?u8 = 3;
while (counter) |c| {
    counter = if (c > 0) c - 1 else null;
}
// цикл крутится, пока значение не станет null

    Теперь for. По массиву с индексом:

    const arr = [_]u8{ 10, 20, 30 };
for (arr, 0..) |item, idx| {
    try out.interface.print("arr[{d}] = {d}\n", .{ idx, item });
}

    По срезу (строке - по байтам):

    for ("hi!") |c| {
    try out.interface.print("{c} ", .{c});
}

    По нескольким последовательностям одновременно - итерации идут параллельно, длина по самой короткой:

    const a = [_]u8{ 1, 2, 3 };
const b = [_]u8{ 4, 5, 6 };
for (a, b) |x, y| {
    try out.interface.print("{d}+{d}={d}\n", .{ x, y, x + y });
}

    По диапазону 0..3 - это 0, 1, 2 (полуинтервал, правая граница не включается):

    for (0..3) |n| {
    try out.interface.print("{d}\n", .{n});
}

    Чтобы for изменял элементы, а не копировал их, итерируйся по указателю - с амперсандом:

    var nums = [_]u8{ 1, 2, 3 };
for (&nums) |*item| {
    item.* *= 10;
}
// nums теперь { 10, 20, 30 }

    break и continue работают как обычно, а для вложенных циклов есть метки:

    const arr2 = [_]u8{ 10, 20, 30 };
outer: for (arr2) |x| {
    for (arr2) |y| {
        if (y == 20) continue :outer; // пропустить остаток внешней итерации
        if (x == 30) break :outer;    // выйти из обоих циклов
    }
}

    И последнее - цикл может быть выражением, которое возвращает значение через break:

    const result = blk: while (true) {
    break :blk 99;
};
// result == 99

    Смотрим в сурсы: что там под капотом¶

    Циклы - это фича языка, но в стандартной библиотеке полно живых примеров, как их пишут на практике. Возьми сравнение строк std.mem.eql из lib/std/mem.zig - там for идет по двум срезам сразу:

    for (a, b) |a_elem, b_elem| {
    if (a_elem != b_elem) return false;
}

    Два среза, одна пара элементов на итерацию, никаких ручных индексов. Это самый идиоматичный способ сравнивать две коллекции поэлементно.

    А вот классический while с выражением продолжения в поиске подстроки findPosLinear из lib/std/mem.zig:

    var i: usize = start_index;
const end = haystack.len - needle.len;
while (i <= end) : (i += 1) {
    if (eql(T, haystack[i..][0..needle.len], needle)) return i;
}
return null;

    Обрати внимание на : (i += 1) - шаг инкремента вынесен в заголовок, а тело занимается только поиском. Еще одна вариация - обратный проход в findLastLinear (lib/std/mem.zig):

    var i: usize = haystack.len - needle.len;
while (true) : (i -= 1) {
    if (mem.eql(T, haystack[i..][0..needle.len], needle)) return i;
    if (i == 0) return null;
}

    Тут условие - просто true (бесконечный цикл), а выход сделан через return. Это стандартный прием, когда "условие выхода" живет внутри тела и его неудобно выносить в заголовок.

    Где можно споткнуться¶

    1. Нет сишного for (init; cond; step). Забудь про for (i = 0; i < n; i++). В Zig это либо while (i < n) : (i += 1), либо for (0..n) |i|. Оба читаются лучше, потому что роли разнесены.

    2. Переменная for неизменяема. for (arr) |item| дает копию элемента, и это const - item *= 10 не скомпилируется (cannot assign to constant). Хочешь менять - итерируй по &arr и получай |*item|, а внутри разыменовывай item.*.

    3. continue не пропускает выражение продолжения. В while (i < 5) : (i += 1) вызов continue все равно выполнит i += 1. Это удобно (нет бесконечных циклов из-за забытого инкремента), но если шаг зависит от условия, учитывай это.

    4. Диапазон 0..n не включает n. for (0..3) |i| даст 0, 1, 2. Это полуинтервал [0, 3), как в Python. Левая граница включается, правая - нет.

    5. Нет do..while. Нужен цикл с проверкой в конце - пиши while (true) { ... break; } и ставь break там, где нужно выйти. Так же делают и в стандартной библиотеке, смотри пример выше.

    6. Метки идут строго перед циклом. Синтаксис outer: for (...), и в break :outer / continue :outer двоеточие обязательно. Без метки break выходит только из ближайшего цикла.

    7. for по нескольким срезам идет до самого короткого. Если длины разные, лишние элементы длинного среза молча игнорируются. Нужно точное соответствие - проверяй длины заранее или используй вариант с проверкой.

    8. Оператор % работает только с беззнаковыми. В теле цикла часто считаешь остаток от деления: if (i % 3 == 0). Но если i знаковое (i32, i64), то % не скомпилируется - Zig требует явно указать, какой остаток нужен: @rem (знак от делимого) или @mod (знак от делителя). Для знаковых целых пиши @rem(i, 3), для беззнаковых % годится.
