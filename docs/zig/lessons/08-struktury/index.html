    8. Структуры¶

    Зачем это нужно и в чем прикол¶

    Структура - это способ собрать данные под одним именем: несколько полей с типами, плюс функции, которые с этими полями работают. В Zig нет классов и нет наследования - есть просто struct, внутри которого лежат и данные, и методы.

    Главный прикол Zig - в том, как структура располагается в памяти. В C поля лежат строго в том порядке, в котором ты их объявил, и между ними зияют дыры выравнивания. В Zig по умолчанию компилятор сам переставляет поля, чтобы убрать лишний padding. Возьми структуру из трех полей { a: u8, b: u32, c: u8 }:

    • в C она заняла бы 12 байт (u8 + 3 байта дыры + u32 + u8 + 3 байта дыры);
    • в Zig компилятор переставит поля в b, a, c и уложится в 8 байт.

    Ты не платишь за то, что не используешь. А если нужен именно C-порядок (для FFI или файлового формата), ты говоришь об этом явно ключевым словом extern. Есть и третий режим - packed, когда поля упаковываются впритык, бит к биту.

    Базовый синтаксис¶

    Объявление и создание:

    const std = @import("std");

const Point = struct {
    x: i32,
    y: i32,
};

pub fn main(init: std.process.Init) !void {
    var buffer: [4096]u8 = undefined;
    var out = std.Io.File.stdout().writerStreaming(init.io, &buffer);

    const p = Point{ .x = 3, .y = 4 };
    try out.interface.print("x={d} y={d}\n", .{ p.x, p.y });

    try out.flush();
}

    Структура - это значение, ее тип описывается как struct { ... }. Экземпляр создается литералом Point{ .x = 3, .y = 4 } - поля через точку. Каждое поле без значения по умолчанию обязано быть заполнено, иначе ошибка компиляции missing struct field.

    Поля со значениями по умолчанию:

    const Player = struct {
    name: []const u8,
    hp: u32 = 100,
    score: u32 = 0,
};

const hero = Player{ .name = "hero" }; // hp и score берутся из значений по умолчанию

    Методы - это обычные функции, объявленные внутри struct, с явным параметром self. Никакого неявного this:

    const Point = struct {
    x: i32,
    y: i32,

    fn distance2(self: Point) i32 {
        return self.x * self.x + self.y * self.y;
    }
};

    Вызываются через точку: p.distance2(). Хочешь менять поля внутри метода - принимай указатель:

    const Counter = struct {
    count: u32 = 0,

    const Self = @This(); // @This() - тип текущей структуры

    pub fn incr(self: *Self) void {
        self.count += 1;
    }
};

var c = Counter{};
c.incr(); // c.count == 1

    Тут два идиоматических момента: const Self = @This() избавляет от повторения имени структуры, а *Self дает методу мутировать экземпляр. Точка c.incr() сама передает указатель - компилятор видит, что параметр это *Counter, и подставляет &c.

    Изменение полей напрямую работает только на var-экземпляре:

    var p = Point{ .x = 3, .y = 4 };
p.x = 10; // ок

const q = Point{ .x = 1, .y = 2 };
// q.x = 5; // ошибка: cannot assign to constant

    Смотрим в сурсы: что там под капотом¶

    Как компилятор описывает структуру? Через @typeInfo, который возвращает Struct из lib/std/lang.zig:

    pub const Struct = struct {
    is_tuple: bool,
    layout: ContainerLayout,
    /// Always `null` if `layout != .@"packed"`.
    backing_integer: ?type,

    field_names: []const [:0]const u8,
    field_types: []const type,
    field_attrs: []const FieldAttributes,

    decl_names: []const [:0]const u8,
    // ...
};

    Поля раскладываются по полочкам: имена отдельно, типы отдельно, атрибуты отдельно. is_tuple различает именованные структуры и анонимные кортежи, а layout задает способ укладки. Три режима из lang.zig:

    pub const ContainerLayout = enum(u2) {
    auto,
    @"extern",
    @"packed",
};

    auto - компилятор сам оптимизирует порядок полей. @"extern" - C-порядок, поля как объявил, с обычным выравниванием. @"packed" - битовая упаковка впритык.

    Значения по умолчанию хранятся в атрибутах поля - смотри FieldAttributes в lang.zig:

    pub const FieldAttributes = struct {
    @"comptime": bool = false,
    @"align": ?usize = null,
    default_value_ptr: ?*const anyopaque = null,
    // ...
};

    default_value_ptr - указатель на значение по умолчанию, стертый до anyopaque. Когда ты пишешь hp: u32 = 100, компилятор кладет 100 в бинарник и ставит сюда указатель на него. Поэтому при создании Player{ .name = "hero" } пропущенные поля заполняются из этого указателя.

    Посмотрим укладку вживую. Одна и та же тройка полей { a: u8, b: u32, c: u8 }:

    const Auto = struct { a: u8, b: u32, c: u8 };
const External = extern struct { a: u8, b: u32, c: u8 };

@sizeOf(Auto)      // 8
@sizeOf(External)  // 12

    Разница в 4 байта - это тот самый padding, который auto-режим убирает. А вот как Auto переставил поля - через @offsetOf:

    @offsetOf(Auto, "a")  // 4
@offsetOf(Auto, "b")  // 0
@offsetOf(Auto, "c")  // 5

    Поле b (4 байта, требует выравнивания 4) встало на смещение 0, а два байта a и c прижались к нему на смещения 4 и 5. Итог 8 байт. В extern-режиме порядок как в C: a на 0, три байта дыры, b на 4, c на 8, еще три байта дыры - 12 байт. Именно поэтому для FFI и бинарных форматов нужен явный extern, иначе полагаться на порядок полей нельзя.

    А packed - это про битовую упаковку. Поля могут занимать доли байта:

    const Flags = packed struct {
    a: u3,
    b: u1,
    c: u4,
};

@sizeOf(Flags)  // 1

    Три поля в один байт: u3 + u1 + u4 = ровно 8 бит. Это то, ради чего packed существует.

    Где можно споткнуться¶

    1. Пропустил поле - не соберется. Литерал S{ .a = 1 } для struct { a: u8, b: u8 } дает error: missing struct field: b. Исключение - только поля со значениями по умолчанию. Это ловит опечатки на этапе компиляции.

    2. const-экземпляр неизменяем целиком. const p = Point{...}; p.x = 5; не выйдет - cannot assign to constant. Изменяемость структуры определяется тем, как ты объявил переменную: var - поля можно менять, const - нет. Это распространяется и на вложенные структуры.

    3. В auto-режиме не полагайся на порядок полей. Смещения полей - дело компилятора. Если записываешь структуру в файл или отдаешь в C - используй extern. А если нужна максимально плотная упаковка (протоколы, регистры, флаги) - packed.

    4. У метода нет неявного this. В отличие от C++/Python, получатель пишется явно первым параметром: fn area(self: Rectangle) u32. Без этого параметра функция - просто свободная функция внутри namespace структуры, а не метод.

    5. Нет классов и наследования. Не ищи class, extends, виртуальные методы. Композиция через вложенные структуры и указатели. Полиморфизм в Zig делается иначе - через union(enum) и @fieldParentPtr, но это отдельная тема.

    6. packed-структуры медленнее в работе с отдельными полями. Поле в packed-структуре может не попадать в границы байта, и чтение требует битовых операций. packed - это про компактность хранения, а не про скорость доступа.
