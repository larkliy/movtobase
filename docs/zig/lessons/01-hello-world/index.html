    1. Первый hello world¶

    Зачем это нужно и в чем прикол¶

    В C ты пишешь int main(int argc, char** argv) и молча ждешь, что ОС подкинет тебе аргументы и переменные окружения. В Python точка входа - это вообще не функция, а просто "все, что сверху скрипта". Никто не спрашивает, откуда берутся sys.argv и os.environ.

    Zig делает иначе: функция main получает на вход готовый, собранный для тебя объект со всем окружением процесса. Ты явно видишь, что у твоей программы есть аргументы командной строки, переменные окружения, аллокатор и подсистема ввода-вывода. Ничего не появляется "из воздуха".

    И да, сразу важная штука: эта версия Zig (0.17.0-dev) недавно переехала на новую подсистему I/O. Если ты гуглил std.debug.print и std.io.getStdOut() - забудь, это прошлое. Дальше разберем, что стало вместо этого.

    Базовый синтаксис¶

    Вот минимальная программа, которая реально собирается на текущем мастере:

    const std = @import("std");

pub fn main(init: std.process.Init) !void {
    var buffer: [4096]u8 = undefined;
    var stdout = std.Io.File.stdout().writerStreaming(init.io, &buffer);

    try stdout.interface.print("Hello, {s}!\n", .{"world"});
    try stdout.flush();
}

    Разбираем по строчкам:

    • const std = @import("std"); - @import это встроенная функция, она подключает стандартную библиотеку на этапе компиляции. Никакого линкера-рантайма, как в C с #include и заголовочниками.
    • pub fn main(init: std.process.Init) !void - точка входа. Заметь тип параметра: std.process.Init, готовый пакет окружения. А !void означает "либо ничего не возвращаю, либо ошибку". Подробнее про ! разберем в отдельном уроке, пока считай это "может вернуть ошибку".
    • var buffer: [4096]u8 = undefined; - стековый буфер для вывода. Никакого неявного выделения памяти из кучи, мы сами даем писателю куда складывать байты.
    • std.Io.File.stdout() - получаем файл стандартного вывода.
    • .writerStreaming(init.io, &buffer) - оборачиваем его в буферизованный writer, который пишет через нашу подсистему I/O (init.io) и использует наш буфер.
    • try stdout.interface.print("Hello, {s}!\n", .{"world"}); - собственно печать. {s} - плейсхолдер строки, .{...} - кортеж аргументов.
    • try stdout.flush(); - выталкиваем буфер в реальный файл. Без этого вывод может не долететь до терминала.

    Есть и совсем короткий вариант для ленивых:

    const std = @import("std");

pub fn main(init: std.process.Init) !void {
    try std.Io.File.stdout().writeStreamingAll(init.io, "Hello, world!\n");
}

    writeStreamingAll внутри делает "создай writer, запиши байты, сбрось буфер" одной строкой. Для hello world - самое то.

    Смотрим в сурсы: что там под капотом¶

    Начнем с того, кто вообще вызывает main. Это lib/std/start.zig. Когда компилятор собирает исполняемый файл, он прилинковывает стартовый код, который экспортирует символ _start. Дальше цепочка такая: _start -> callMain (start.zig:786).

    Вот что делает callMain, по сути:

    inline fn callMain(args: std.process.Args.Vector, environ: std.process.Environ.Block) u8 {
    // ... определение gpa: в debug/safe режиме это SafeAllocator с проверкой утечек
    const gpa = if (use_safe_allocator)
        safe_allocator.allocator()
    else if (builtin.link_libc)
        std.heap.c_allocator
    // ...

    var arena_allocator = std.heap.ArenaAllocator.init(arena_backing_allocator);
    var threaded: std.Io.Threaded = .init(gpa, .{ ... });
    // ... парсинг окружения, преопенсы

    return wrapMain(root.main(.{
        .minimal = .{ .args = ..., .environ = ... },
        .arena = &arena_allocator,
        .gpa = gpa,
        .io = threaded.io(),
        .environ_map = &environ_map,
        .preopens = preopens,
    }));
}

    То есть еще до твоего main рантайм поднял: аллокатор общего назначения (в debug-сборке - с проверкой утечек), арену, потоковый I/O, карту переменных окружения. Все это пакуется в std.process.Init и передается тебе. Определение структуры лежит в lib/std/process.zig:31:

    pub const Init = struct {
    minimal: Minimal,       // args + environ
    arena: *std.heap.ArenaAllocator,
    gpa: Allocator,
    io: Io,
    environ_map: *Environ.Map,
    preopens: Preopens,
};

    Дальше wrapMain (start.zig:840) смотрит на то, что вернула твоя функция. Разрешенные типы возврата строго такие: void, !void, noreturn, u8, !u8. Если main вернул ошибку, wrapMain ловит ее, пишет в лог через std.log.err и возвращает код выхода 1:

    const unwrapped_result = result catch |err| {
    std.log.err("{t}", .{err});
    // ...
    return 1;
};

    Заметь {t} - это формат-спецификатор для имени ошибки (он же подходит для энумов).

    Теперь про сам вывод. std.Io.File.stdout() в lib/std/Io/File.zig:91 просто оборачивает нативный дескриптор в структуру File:

    pub fn stdout() File {
    return switch (native_os) {
        .windows => .{
            .handle = std.os.windows.peb().ProcessParameters.hStdOutput,
            .flags = .{ .nonblocking = false },
        },
        else => .{
            .handle = std.posix.STDOUT_FILENO,
            .flags = .{ .nonblocking = false },
        },
    };
}

    На Windows handle берется прямо из PEB процесса, на POSIX - это файловый дескриптор 1. Никакой магии, просто число.

    А print живет не там, где ты мог бы ожидать. writerStreaming возвращает File.Writer (это lib/std/Io/File/Writer.zig), у которого внутри есть поле interface: Io.Writer. Сам print, writeAll, flush - методы этого Io.Writer из lib/std/Io/Writer.zig:697. Поэтому и пишем stdout.interface.print(...).

    Сам print - это comptime-магия: строка формата разбирается на этапе компиляции, аргументы проверяются по типам. Есть жесткое ограничение - максимум 32 аргумента на один вызов, иначе @compileError("32 arguments max are supported per format call").

    Где можно споткнуться¶

    1. Забыть flush. Writer буферизует в твой стековый buffer. Пока буфер не заполнился, байты никуда не ушли. Завершил программу без flush - "Hello, world!" просто не появился на экране. Классика.

    2. Написать stdout.print(...) вместо stdout.interface.print(...). File.Writer - это отдельная структура, у которой print нет. Компилятор честно скажет error: no field or member function named 'print' in 'Io.File.Writer'. Спотыкание на этом - норма, просто помни про .interface.

    3. Устаревший API из гайдов. std.debug.print("hi", .{}) еще существует, но теперь пишет в stderr (и с 64-байтным буфером), а std.io.getStdOut() в этой версии уже нет вообще. Если дергаешь код из старого туториала - получишь ошибку "no member". Ориентируйся на std.Io.File.stdout().

    4. Неправильный тип возврата у main. Вернул i32 или error без ! - компилятор воткнет expected return type of main to be 'void', '!void', 'noreturn', 'u8', or '!u8'. Хочешь свой код выхода - возвращай u8.
