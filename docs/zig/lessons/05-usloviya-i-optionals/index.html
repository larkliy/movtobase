    5. Условия if/else и optionals¶

    Зачем это нужно и в чем прикол¶

    В C и Python есть неявная правдивость: if (x) работает с чем угодно - с числами, указателями, строками. 0 ложен, "" ложен, NULL ложен, и границы этой логики постоянно приводят к багам вроде "условие сработало на пустой строке".

    В Zig if принимает ровно один тип - bool. Написал if (5) - получишь ошибку компиляции expected type 'bool', found 'comptime_int'. Никакой магии, никаких догадок: условие либо true, либо false.

    Вторая тема - optionals. В C отсутствие значения выражается нулевым указателем NULL, и любая функция может внезапно вернуть NULL, а ты про это узнаешь только по сегфолту. В Zig отсутствие значения - это отдельный тип. ?u8 значит "либо u8, либо null", и null не свалится тебе на голову оттуда, где ты его не ждешь: обычный u8 не может быть null в принципе.

    Красота в связке этих двух идей - паттерн захвата. Вместо "проверь на null, потом достань значение":

    if (opt != null) {
    const v = opt.?;  // так не делают
}

    Zig пишет это одним движением:

    if (opt) |v| {
    // v доступна здесь, и она гарантированно не null
}

    Базовый синтаксис¶

    Обычный if/else. Обрати внимание: else обязан стоять на той же строке, что и закрывающая скобка } - в Zig это синтаксическое требование:

    const std = @import("std");

fn classify(n: i32) []const u8 {
    if (n > 0) {
        return "positive";
    } else if (n < 0) {
        return "negative";
    } else {
        return "zero";
    }
}

    Для коротких веток без скобок все пишется в одну строку:

    if (n > 0) return "positive" else if (n < 0) return "negative" else return "zero";

    if в Zig - это выражение, оно возвращает значение:

    const a = 10;
const label = if (a > 5) "big" else "small";

    Теперь optionals. Объявляются знаком вопроса:

    var maybe: ?u8 = null;   // сейчас значения нет
maybe = 42;              // а теперь есть

    Три способа достать значение:

    // 1. захват в if - значение видно только внутри ветки
if (maybe) |v| {
    std.debug.print("value: {d}\n", .{v});
} else {
    std.debug.print("null\n", .{});
}

// 2. orelse - подставить значение по умолчанию
const val = maybe orelse 0;

// 3. .? - принудительно развернуть; на null упадет с паникой
const unwrapped = maybe.?;

    Паттерн захвата работает и в while, пока значение не станет null:

    var counter: ?u8 = 3;
while (counter) |c| {
    std.debug.print("countdown {d}\n", .{c});
    counter = if (c > 0) c - 1 else null;
}
// напечатает 3, 2, 1, 0 и остановится

    Смотрим в сурсы: что там под капотом¶

    Optional с точки зрения компилятора - это предельно простая структура. В lib/std/lang.zig:789, куда @typeInfo кладет описание типа:

    pub const Optional = struct {
    child: type,
};

    Всего одно поле - тип вложенного значения. Больше ничего не нужно: null это отдельный специальный тег, а не значение вложенного типа.

    Главное, что под капотом происходит с памятью. Возьми ?u8:

    @sizeOf(u8)   // 1
@sizeOf(?u8)  // 2

    Почему 2 байта? Потому что u8 использует все 256 значений от 0 до 255, и свободного "пустого" значения для null не остается. Компилятор добавляет скрытый тег-байт: 1 байт на признак "есть значение или null", 1 байт на сам u8.

    А теперь ?*u8:

    @sizeOf(*u8)   // 8
@sizeOf(?*u8)  // 8

    Тут тега нет вообще, оба по 8 байт. Почему? Потому что указатели и так имеют зарезервированное значение "ноль", которое не указывает ни на какую память. Компилятор просто использует нулевой указатель как представление null - это бесплатно, ноль байт накладных расходов. Та же оптимизация срабатывает и для ?enum, когда у enum есть свободное значение.

    Это и есть идея Zig: null - это явное значение, которое живет в типе, а не указатель на ноль, который можно спутать с чем угодно.

    Где можно споткнуться¶

    1. Нет правдивости. Условие обязано быть bool. Ни if (5), ни if (maybe) не скомпилируются:

    error: expected type 'bool', found '?u8'

    Для optional нужно либо сравнение if (maybe != null), либо паттерн захвата if (maybe) |v|. Между этими двумя вариантами предпочитай второй - он безопаснее, потому что не дает забыть про разворачивание.

    2. else должен быть на одной строке с }. Разнесешь:

    if (cond) {
    foo();
}
else {        // ошибка: expected statement, found 'else'
    bar();
}

    Почему так - Zig не требует скобок вокруг условия и не ставит точку с запятой после if, поэтому перенос else на новую строку делает его отдельным statement. Держи } else { слитно.

    3. .? на null - это паника. .? это не "проверь и продолжь", это "я на 100% уверен, что значение есть, разверни без проверок". На null получишь panic: attempt to use null value со стек-трейсом. Пользуйся им только там, где значение гарантированно есть, иначе - orelse или захват.

    4. orelse обязан дать значение того же типа, что payload. maybe orelse 0 работает, а maybe orelse "нет" - нет, если maybe: ?u8. Значение справа от orelse подставляется ровно в тип вложенного значения.

    5. Optional - это не флаг. ?bool это НЕ три состояния "да/нет/неизвестно". Это два уровня: внешний "есть/нет" и внутренний true/false. ?bool реально занимает три логических состояния, но будь аккуратен - легко запутаться. А ??u8 (optional от optional) - это вообще "может быть null, может быть Some(null), может быть Some(Some(42))", что почти никогда не нужно.
