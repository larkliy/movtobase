    7. Функции¶

    Зачем это нужно и в чем прикол¶

    Функция в Zig - это явный контракт: тип каждого аргумента и тип возврата написаны в сигнатуре. Никакой неявной правдивости, никакого неявного приведения. Если функция вернула i32, она вернула i32, а не "что-то, что можно интерпретировать".

    Три вещи, которые отличают Zig от C/C++ и Python:

    Во-первых, параметры неизменяемы. Аргумент приходит как const, и попытка x += 1 прямо в теле даст cannot assign to constant. Хочешь менять - заведи локальную переменную. Это убирает целый класс багов "ой, я поменял аргумент и вызывающий код про это не знает".

    Во-вторых, нет неявного возврата последнего выражения. В Rust последнее выражение без точки с запятой становится результатом функции, в Zig - нет. Тут return обязателен, и это честно: ты видишь все точки выхода явно.

    В-третьих, дженерики сделаны без отдельного синтаксиса. Никаких <T> и template<>. Просто параметр с comptime или anytype, и компилятор сам генерирует специализацию под конкретный тип в точке вызова.

    Базовый синтаксис¶

    Простая функция:

    const std = @import("std");

fn add(a: i32, b: i32) i32 {
    return a + b;
}

fn noReturn(x: i32) void {
    _ = x; // void - функция ничего не возвращает
}

    fn - ключевое слово, дальше имя, параметры в скобках, тип возврата после скобок, тело в фигурных. Чтобы функцию было видно из других файлов, помечай pub:

    pub fn addPub(a: i32, b: i32) i32 {
    return a + b;
}

    Параметр по умолчанию const. Чтобы его поменять, скопируй в локальную:

    fn mutate(x: i32) i32 {
    var y = x; // локальная копия, можно менять
    y += 1;
    return y;
}

    Теперь дженерики. Два способа. Первый - явный тип-параметр через comptime:

    fn doubleIt(comptime T: type, value: T) T {
    return value * 2;
}

// вызов с конкретным типом
const a = doubleIt(u8, 7);   // 14, тип u8
const b = doubleIt(i32, 7);  // 14, тип i32

    comptime T: type - это параметр, который известен на этапе компиляции и содержит тип. Под каждый вызов компилятор генерирует отдельную версию функции.

    Второй - anytype, тип выводится сам:

    fn identity(value: anytype) @TypeOf(value) {
    return value;
}

    anytype значит "тип определяется из аргумента", а @TypeOf(value) возвращает этот тип как тип возврата.

    inline - просит компилятор встроить тело функции в место вызова:

    inline fn square(x: i32) i32 {
    return x * x;
}

    И наконец - функция это значение. Ее можно положить в указатель и передавать:

    fn double(x: i32) i32 {
    return x * 2;
}

fn applyTwice(f: *const fn (i32) i32, x: i32) i32 {
    return f(f(x));
}

pub fn main(init: std.process.Init) !void {
    var buffer: [4096]u8 = undefined;
    var out = std.Io.File.stdout().writerStreaming(init.io, &buffer);

    try out.interface.print("applyTwice: {d}\n", .{applyTwice(&double, 5)}); // double(double(5)) = 20

    // указатель на функцию
    const fp: *const fn (i32, i32) i32 = &add;
    try out.interface.print("fp: {d}\n", .{fp(10, 20)});

    try out.flush();
}

    Тип указателя на функцию: *const fn (параметры) возврат. Амперсанд &double берет адрес функции.

    Смотрим в сурсы: что там под капотом¶

    Как компилятор описывает функцию? Через @typeInfo, который возвращает структуру Fn из lib/std/lang.zig:848:

    pub const Fn = struct {
    attrs: Attributes,
    is_generic: bool,
    /// `null` means the return type is generic, i.e. it depends on a function argument.
    return_type: ?type,

    /// A `null` element represents either an `anytype` parameter, or a parameter with a generic
    /// type, i.e. where the type depends on a previous function argument.
    param_types: []const ?type,
    param_attrs: []const ParamAttributes,
    // ...
};

    Обрати внимание на return_type: ?type и param_types: []const ?type - тип возврата и параметры опциональны. Для anytype-функции или когда возврат зависит от аргумента, эти поля null. Именно поэтому identity(value: anytype) @TypeOf(value) не имеет "одного" типа - у нее по типу на каждое место вызова. Компилятор помечает такую функцию is_generic = true.

    Атрибуты функции - это в первую очередь calling convention, lang.zig:164:

    pub const CallingConvention = union(enum(u8)) {
    auto,
    @"inline",
    // ... x86_64_sysv, x86_64_win, c, winapi и так далее
};

    auto - стандартный для Zig (никаких гарантий по регистрам, только внутри компиляции), @"inline" - то, что делает ключевое слово inline, а c и winapi нужны для взаимодействия с сишными библиотеками.

    Теперь посмотри, как дженерики выглядят в реальной стандартной библиотеке. std.math.maxInt из lib/std/math.zig:1437:

    pub fn maxInt(comptime T: type) comptime_int {
    const info = @typeInfo(T).int;
    return (1 << (info.bits - @intFromBool(info.signedness == .signed))) - 1;
}

    comptime T: type - тип известен при компиляции, значит и вся функция выполняется при компиляции, возвращая comptime_int. А std.mem.print из lib/std/mem.zig:5209 использует anytype для аргументов форматирования:

    pub fn print(buffer: []u8, comptime format: []const u8, args: anytype) PrintError![]u8 {
    // ...
}

    Тут format - строка формата, известная на этапе компиляции, а args - кортеж любых значений. Комбинация comptime format + anytype args и есть стандартный паттерн для "переменное число аргументов любого типа".

    Где можно споткнуться¶

    1. Параметры неизменяемы. fn f(x: i32) { x += 1; } не соберется - cannot assign to constant. Это не ограничение, а защита: вызывающий код не ждет, что функция поменяет его переменную. Нужен результат - верни новое значение, нужен побочный эффект - передай указатель.

    2. Нет неявного возврата. Написал в конце тела x * 2 без return - получишь expected ';' after statement, потому что компилятор считает это выражением-оператором, а не возвратом. Точки выхода всегда явные.

    3. Тип возврата обязателен. В отличие от многих языков, Zig не выводит тип возврата функции - его надо писать всегда. Это осознанное решение: сигнатура функции это публичный контракт, и он не должен зависеть от реализации в теле.

    4. anytype порождает по функции на каждый тип. fn id(x: anytype) это не одна функция, а шаблон. Вызвал с u8 и с []const u8 - получил две разные функции в бинарнике. Для маленьких утилит это ок, но для больших функций раздувает код. Если набор типов известен заранее - лучше comptime T: type.

    5. Указатель на inline-функцию - только comptime. inline-функцию нельзя просто взять по адресу и положить в обычный указатель, потому что она семантически встроена в место вызова. Если функция должна быть указателем - не делай ее inline.

    6. Типы указателей на функции строгие. *const fn (i32) i32 и *const fn (i64) i64 - разные типы. При передаче функции как аргумента сигнатуры должны совпадать в точности, никакого неявного приведения.
